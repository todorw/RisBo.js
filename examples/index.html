Signal in,node out.

RisBo wires every signal straight to the one DOM node that reads it. Change the value and that node updates — nothing is diffed, nothing else re-runs, and there's no build step in between.

Why RisBo

Everything a UI needs, nothing it doesn't.

Reactivity, components, control flow, routing, a store and server rendering — a toolkit small enough to read end to end in one sitting.

Fine-grained

Updates touch only the text node or attribute that depends on a signal — never a whole component tree.

No build step

Standard ES modules, wired point to point. Drop it in a <script type="module"> and ship.

Tiny & fast

No virtual DOM, no diffing pass. Bindings connect straight to the DOM at creation time.

Async built in

resource() tracks a promise with loading and error state, and refetches when its input changes.

Routing & store

A History-API router with path params, plus a reactive store with batched actions.

Server rendering

renderToString() grounds the same components to an HTML string — no browser required.

The whole idea

A signal declares state. A binding reads it.

Nothing else has to happen for the two to stay in sync — RisBo connects them once, at creation time.

CH1counter.js
import { signal, computed, h, render } from "risbo";

function Counter() {
  const count = signal(0);
  const parity = computed(() =>
    count() % 2 === 0 ? "even" : "odd");

  return h("div", { class: "card" },
    h("p", null, () => `Count: ${count()} (${parity()})`),
    h("button", { "on:click": () => count.set(n => n + 1) },
      "Increment"));
}

render(Counter, document.querySelector("#app"));
CH2todo.js — control flow
import { signal, h, For, Show } from "risbo";

const todos = signal([{ id: 1, text: "Ship it", done: false }]);

const List = () =>
  h(Show, { when: () => todos().length, fallback: () => "All clear" },
    () => h("ul", null,
      h(For, { each: () => todos(), by: t => t.id },
        (todo) => h("li", { class: todo.done && "done" },
          todo.text))));

// Reorder or remove items — RisBo reuses the matching DOM nodes.
