Why RisBo

Everything you need, nothing you don't.

A complete toolkit — reactivity, components, control flow, routing, a store and server rendering — in a library you can read end to end.

◑

Fine-grained

Updates touch only the text node or attribute that changed — not whole component trees.

⌘

No build step

Standard ES modules. Drop it in a <script type="module"> and ship.

⊹

Tiny & fast

No virtual DOM diffing. Bindings wire straight to the DOM at creation time.

⟲

Async built in

resource() tracks promises with loading and error state, and refetches reactively.

⎇

Routing & store

A History-API router with params, plus a reactive store with batched actions.

⇪

Server rendering

renderToString() renders the same components to HTML — no browser required.

The whole idea

Signals in, DOM out.

Declare reactive state, return DOM. RisBo keeps them in sync automatically.

counter.js
import { signal, computed, h, render } from "risbo";

function Counter() {
  const count = signal(0);
  const parity = computed(() =>
    count() % 2 === 0 ? "even" : "odd");

  return h("div", { class: "card" },
    h("p", null, () => `Count: ${count()} (${parity()})`),
    h("button", { "on:click": () => count.set(n => n + 1) },
      "Increment"));
}

render(Counter, document.querySelector("#app"));
todo.js — control flow
import { signal, h, For, Show } from "risbo";

const todos = signal([{ id: 1, text: "Ship it", done: false }]);

const List = () =>
  h(Show, { when: () => todos().length, fallback: () => "All clear" },
    () => h("ul", null,
      h(For, { each: () => todos(), by: t => t.id },
        (todo) => h("li", { class: todo.done && "done" },
          todo.text))));

// Reorder or remove items — RisBo reuses the matching DOM nodes.
